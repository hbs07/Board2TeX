## 2. 工程与环境问题

### 2.1 中文文件名导致"文件不存在"

- **现象**:导入 `微信图片_xxx.jpg` 弹 `FileNotFoundError`,但文件确实存在。
- **根因**:Windows 上 `cv2.imread` 走 ANSI 路径,遇到中文文件名直接返回 `None`;
  代码把 `None` 当成"文件不存在"。
- **修复**:改用字节流读取——

  ```python
  data = np.fromfile(path, dtype=np.uint8)
  img = cv2.imdecode(data, cv2.IMREAD_COLOR)
  ```

  并区分错误:文件不存在 → `FileNotFoundError`;存在但解码失败 → `ValueError`。
- **证据**:`preprocess/pipeline.py`,提交 `cc4f6c2`;新增"中文名复制样图再读取"单测。
- **一句话讲法**:"不是文件丢了,是 OpenCV 不认中文路径。"

### 2.2 Qt 与 torch 的加载顺序导致崩溃

- **现象**:GUI 点「运行识别」时程序直接退出;日志为
  `OSError: [WinError 1114] ... c10.dll` 或 `Windows fatal exception: access violation`。
- **根因**:Windows 上先 `import PyQt5`、再 `import torch`,torch 的 DLL 初始化失败;
  反过来先 torch 再 Qt 就正常。命令行跑 `main.py` 没问题,所以只在 GUI 暴露。
- **修复**:新增 `gui/torch_preload.py`,所有导入 PyQt5 的模块都先导入它。
- **证据**:`gui/torch_preload.py`、`gui/main_window.py` 顶部注释;提交 `a9794ce`。
- **一句话讲法**:"同一个库,导入顺序不同,一个能跑一个崩。"

### 2.3 每次编译弹黑色命令行窗口

- **现象**:实时预览每改一次内容,屏幕闪一个黑框。
- **根因**:GUI 用 `pythonw` 启动(无控制台),而 `xelatex / pdflatex / pdftoppm`
  是控制台程序,Windows 会给每个子进程新建控制台。
- **修复**:统一走 `run_hidden()`,加 `CREATE_NO_WINDOW`。
- **证据**:`gui/exporter.py`、`gui/preview.py`;提交 `a9794ce`。

### 2.4 高 DPI 下预览"发糊"

- **现象**:预览页文字发虚,截图看正常,真实窗口糊。
- **根因**:屏幕 200% 缩放,`devicePixelRatio = 2`;原实现按"逻辑像素"渲染
  (约 1088px),Qt 再铺到 2176 个物理像素上,等于放大 2 倍。
- **修复**:渲染宽 = 逻辑宽 × DPR,并 `pixmap.setDevicePixelRatio(dpr)`,物理像素 1:1。
- **证据**:`gui/preview_pane.py`、`gui/preview.py`;提交 `a9794ce`。

### 2.5 pytest 误把冒烟脚本当测试

- **现象**:`pytest` 一跑就是 4.5 分钟,还会加载 PaddleOCR/pix2tex。
- **根因**:`tools/smoke_test.py` 命中 pytest 的 `*_test.py` 收集规则,导入即执行。
- **修复**:改名 `tools/env_smoke.py`,并加 `pytest.ini` 限定 `testpaths=tests`。
- **证据**:提交 `dee0962` / `ffa0557`。

### 2.6 xelatex 不接受反斜杠路径

- **现象**:Windows 路径 `data\exports\result.tex` 传给 xelatex,
  报 `Undefined control sequence`(把 `\r` 当控制符)。
- **修复**:`compile_pdf` 内统一把 `\` 转 `/`。
- **证据**:`gui/exporter.py`;提交 `16d43fd`。

## 3. 算法与数据问题

### 3.1 测试样图与项目边界不一致

- **现象**:`assets/test_text.png` 只有一行中文,而 MVP 是"英文 + 公式";
  同时 B 的"切出多行"验收永远不可能通过。
- **修复**:用脚本生成 5 行英文板书(3 文字 + 2 公式),保留原路径,
  所有既有命令继续有效;生成脚本 `tools/make_test_assets.py`。
- **证据**:提交 `bf02b85`。

### 3.2 上下标碎片导致整页 order 错位

- **现象**:`\sum_{k}` 的下标 `k` 与 Σ 之间有一行空白,被切成独立 Region,
  多出一个"25×33 的小块",后面所有行号整体后移。
- **修复**:`split_lines` 后增加 `_merge_fragments`:间隙 ≤ 上一行高度 40%、
  且本段高度 ≤ 上一行 60% 时并回上一行。
- **证据**:提交 `4b75706`;评估集 4/4 张行数正确。

### 3.3 短文本行被误判成公式

- **现象**:`Limits` 这种短标题被判成 formula,送进 pix2tex 输出乱码。
- **根因**:原规则只看"高宽比",短文本行和公式行一样"紧凑"。
- **修复**:改用 **墨迹占比**(公式留白多)+ 紧凑度 + 字高差异 + 面积离群记分;
  在 15 行标注样例上调参,达到 15/15。
- **证据**:`layout/classify.py`;提交 `4b75706`。

### 3.4 公式行的"低置信度"没有意义

- **现象**:所有公式行都标红,用户无法判断该改哪行。
- **根因**:pix2tex 不输出置信度,代码给了固定经验值 0.8,低于阈值 0.85。
- **修复**:文字行仍看置信度;公式行改看"空结果 / 花括号是否配对",并加图例说明。
- **证据**:`gui/main_window.py`、`gui/style.py`;提交 `b8c33ad`。

### 3.5 印刷体模型无法处理手写/双栏(核心边界)

- **现象**:真实手写双栏黑板(Taylor 公式)自动切行只得到 **1 个 Region**,
  识别结果是整段乱码;PaddleOCR 整图识别置信度仅 **0.61**。
- **根因**:
  1. 行与行之间没有整行空白(手写拥挤 + 上下标),投影切行失效;
  2. 板上每列都有墨迹,整宽投影永远 >0,无法分栏;
  3. PaddleOCR/pix2tex 是印刷体模型,手写数学不在训练分布内。
- **结论**:这不是参数问题,是模型能力边界;调阈值/加合并都救不回来。
- **解决**:新增 **AI 识别**入口,把整图交给视觉大模型(Westlake HPC,OpenAI 兼容接口),
  模型直接返回逐行 JSON;同一张手写板实测 **11 行 / 约 10 秒**,预览可编译。
- **证据**:`recog/vlm.py`、`gui/main_window.py`;提交 `32ab982`。

### 3.6 公式识别的已知误差

- **现象**:`x` 被认成 `X`(大小写);`e^{i\pi}+1=0` 稳定识别失败。
- **量化**(合成评估集 15 行):
  - 行数正确 100%
  - 行分类 100%
  - 文字 CER 1.3%
  - 公式完全匹配 50%,相似度 69.8%
- **口径**:合成板书(白底、印刷体、无透视),不代表手机实拍;
  实拍可用率按 `eval/labels.csv` + `--mode manual` 统计。
- **证据**:`docs/03-report/Board2TeX_评估报告.md`、`eval/`。

## 4. 交互与集成问题

### 4.1 预览只显示源码

- **现象**:点「预览」看到的是一段 LaTeX 文本,不是排版结果。
- **修复**:预览 = 当前 tex → 编译 PDF → 逐页转 PNG → 弹窗/侧栏显示(所见即导出)。
- **证据**:`gui/preview.py`;提交 `9829064`。

### 4.2 实时预览太慢

- **现象**:改一行要等约 4 秒,像卡住。
- **根因**:xelatex 每次完整编译约 **3.2s**(字体加载占大头)。
- **修复**:预览改用 pdflatex(**0.6s**),失败自动回退 xelatex;导出仍用 xelatex;
  再加 300ms 防抖 + 内容未变不重编。实际编辑后约 **1 秒**更新。
- **证据**:`gui/exporter.py`、`gui/preview_pane.py`;提交 `176f575`。

### 4.3 编辑后导出的是旧内容

- **现象**:在界面改了一行,导出的 tex 还是识别原文。
- **修复**:导出/预览前统一 `_rebuild_tex()`,用当前 blocks 重建正文。
- **证据**:`gui/main_window.py`;提交 `bfc89ac`。

### 4.4 图片被裁切

- **现象**:窗口或分隔条一变,左侧原图只显示一部分。
- **根因**:只在导入时按当时控件尺寸缩放一次。
- **修复**:保存原始 QPixmap,尺寸变化时重新等比适配(`_fit_image`)。
- **证据**:提交 `54408bf`。

### 4.5 多张板书的组织

- **追加导入**:只识别新图片,已有内容与手工修改不被覆盖(`append_documents`)。
- **调整顺序**:整张图片拖动/上移下移,不重新识别(`reorder_pages`)。
- **行内移动**:每行 ↑/↓,支持跨页,页大小同步调整(`move_block`)。
- **证据**:`654e2a6`、`f9b71e3`、`f129ce0`。

### 4.6 手动切分功能被移除

- **尝试**:先做了"用户自己框选每一行"的方案(`3e0c67a`)。
- **结果**:能解决切行,但识别仍是印刷体模型,手写公式依旧不可用;
  操作成本高、收益低。
- **决定**:接入 VLM 后删除该功能(`1bb5bab`),保留更自动的「AI 识别」。

## 6. 局限与 Future Work

1. **双栏自动切分**:目前依赖视觉模型;本地链路没有做栏分割。
2. **手写识别**:本地模型不可用,需联网调用视觉大模型(有网络/成本约束)。
3. **透视与反光**:MVP 要求拍摄端正;未做透视矫正。
4. **中文**:模板为 article + 英文;中文板书需换 ctexart + 中文 OCR。
5. **实时性**:预览是"停手后约 1 秒",不是 Typora 式逐键渲染。
6. **评估规模**:合成集 15 行;实拍样本仍偏少。

## 7. 期末 pre 可用的三个故事

1. **中文路径**:文件明明在,程序说找不到——最后定位到 OpenCV 的 ANSI 路径限制。
   教训:错误信息要区分"不存在"和"读不了"。
2. **只在真实窗口复现的崩溃**:命令行一切正常,GUI 点识别就退;
   根因是 PyQt5 与 torch 的 DLL 加载顺序。教训:测试要覆盖真实启动路径。
3. **从"1 个乱码块"到"11 行可编辑 LaTeX"**:
   手写双栏黑板让本地模型彻底失效,最终改用视觉大模型;
   同时保留本地链路给印刷体,形成"快/准"两条路线。
