# Board2TeX —— 板书 → LaTeX 一键归档工具

**ICSP (Track A) 期末 Project Proposal 大纲 · Fall 2026**

> 团队成员:胡秉善(组长)、郭佳欣、陶谱州、李若宸
> 课程节点:Week 4 组队 → **Week 5 期中汇报(交 proposal PDF)** → Week 16 末交报告 → Week 17 决赛展示
>
> **简化版说明**:全组均为大一学生。相比第一版设想,本版**砍掉了透视矫正**(轮廓检测 + homography 的调试成本对新手过高,第一版拍照时尽量拍正即可),保留环境已验证的完整识别主线:PaddleOCR 文字识别 + pix2tex 公式识别 + xelatex 编译导出 PDF。工作量重心放在**人人都在写代码**的模块:图像增强与切行、LaTeX 转义合成、错题本、界面。详见 §2.1、§4、§6。

---

## 0. 一句话介绍

拍一张老师的板书/白板照片,自动完成 **图像增强 → 按行切分 → 英文与公式识别 → 拼接成 .tex → 渲染 PDF**,并提供 **人工校对界面** 与 **错题本归档** 功能。

---

## 1. 背景与意义(Significance)

### 1.1 痛点
- 上课拍板书很快,但复习时要逐字手打公式进 LaTeX/Word,费时且易错;
- 现有工具(Mathpix/Snip 等)按次收费,且只支持"单条公式"截图,不支持**整版板书、英文与公式混排、复习归档**。

### 1.2 目标用户
- 想把板书归档复习的同学;
- 需要把课堂推导整理成讲义/复习资料的助教与老师。

### 1.3 与课程内容的呼应
- 直接应用 Week 16《人工智能》:OCR、深度学习模型调用与评估;
- 预处理、按行切分大量使用 Week 5~7 的 Python 编程与算法思维(列表、循环、数组切片)。

---

## 2. 问题定义

**输入**:一张板书/白板照片(JPG/PNG,拍照时尽量拍正)

**输出**:
1. 增强后的清晰图像;
2. 按阅读顺序拼接好的 `.tex` 文档;
3. 可直接查看的 PDF 渲染结果;
4. 可人工校对的中间结果(保证最终可用)。

### 2.1 MVP 边界(第一版只做)

| 第一版做 ✓ | 列为 Future Work ✗ |
|---|---|
| 单张照片、工整板书(拍照时尽量拍正) | **透视矫正**、多页批量、严重倾斜潦草手写 |
| **单列**版面 | **双列**版面、表格、流程图、几何图形 |
| 英文文字 + 数学公式混排 | 其他语种、乐谱等特殊符号 |
| Windows 桌面 GUI | 移动端 / 网页版 |
| 逐行人工校对 | 行内"文字+公式"自动切块 |

> **本版主动砍掉的高风险项**:① **透视矫正**(本版核心简化点,轮廓检测 + homography 对大一调试成本过高,用"拍照拍正"替代);② 双列版面分析;③ 行内混排切块;④ 反光 inpaint 修复(降级为一句 CLAHE);⑤ 实时逐键重渲染(降级为"点按钮预览")。答辩时说明这是**有意识的取舍**,不是做不出来。

## 3. 系统架构

```
输入照片(拍照时尽量拍正)
  │
  ▼
① 图像预处理
   ├─ 读取 + 缩放(长边 1600)            ← A
   └─ 灰度 + CLAHE + Otsu 二值化 + 裁剪   ← B
  │
  ▼
② 版面分析:水平投影切行 + 每行规则分类(文字/公式)   ← B
   │
   ▼
③ 识别:文字行 → PaddleOCR ;  公式行 → pix2tex          ← C
   │   (pix2tex 封装由 A 给出已验证模板)
   ▼
④ LaTeX 合成:按行拼接、特殊字符转义、生成 .tex        ← C
   │
   ▼
⑤ 桌面应用(PyQt5)                                     ← A 搭框架 + D 填控件
   ├─ 导入照片 → 点"运行" → 逐行可编辑(低置信度标红)
   ├─ 点"预览"刷新校对结果
   ├─ 导出 .tex / 调用 xelatex 导出 PDF               ← D
   └─ 存入错题本(SQLite:保存 / 列出)                  ← D
```

**技术栈**:Python + OpenCV + PaddleOCR(PP-OCRv5)+ pix2tex(LaTeX-OCR)+ PyQt5 + SQLite。
**环境已由 `check_env.py` 验证通过**(见 `tools/env_check_report.txt`,PaddleOCR 与 pix2tex 均识别成功)。

---

## 4. 技术要点(Difficulty 证据)

> 本版难度定位:不做 CV 数学攻坚,难度来自**完整工程**——四个模块按冻结接口组装联调,以及以下自研点:

1. **[B] 版面行切分与分类**:水平投影找行间空白;用"高宽比 + 连通域"几何特征投票区分"文字行 vs 公式行",人工标注真值调阈值,不拍脑袋定参数。
2. **[C] 英文与公式混排的 LaTeX 合成与编译**:文字转义(`& % _ # $` 等)、公式进 `$$...$$`,保证 xelatex 编译通过。
3. **[D/A] 校对闭环**:低置信度区域标红 → 人工改 → 重新合成导出,保证最终可用。
4. **[A] 集成与工程化**:四人四模块按冻结接口组装成一条龙;骨架、测试图、验证命令、PR 审核保证质量。

> **透视矫正列为 Future Work**:需要轮廓检测与 homography 调试,对大一投入产出比低;第一版拍照时拍正即可满足使用。

## 7. 评估指标(Completeness 量化证明)

- **行切分正确率**:自采 20~30 张工整板书,人工核对标注图,目标 ≥ 90%;
- **行分类准确率**:人工标注真值并调参后,目标 ≥ 80%;
- **端到端可用率**:仅需少量人工修改即可导出正确 `.tex` 的比例,目标 ≥ 70%;
- **全流程演示**:拍照 → 识别 → 校对 → 导出 PDF → 存入错题本,一条龙跑通。

> 样本量 20~30 张,降低采集与标注负担;报告中如实写明样本量。

## 9. 风险与备选方案

| 风险 | 应对 |
|---|---|
| pix2tex 公式识别偶尔输出错误 LaTeX | 校对界面兜底:花括号配对检查 + 低置信度标红;demo 使用精挑样例。 |
| 识别效果不稳定,demo 翻车 | 人工校对界面兜底;现场使用精挑样例。 |
| 被质疑"只是调模型" | 突出自研的切行/分类/转义合成/错题本/评估;附代码量与评估数据。 |
| PaddleOCR/pix2tex 安装失败 | **环境已验证通过**;终极备选:改用 Mathpix API,自研模块不变。 |
| 无 GPU | 只用预训练模型(CPU 推理),不承诺自己训练。 |
| LaTeX 环境缺失 | 导出 PDF 前先检测 `xelatex`,没有则只导出 `.tex` 并提示。 |
| 成员进度不齐 | 主责 + 交叉互补;每周例会与看板盯进度;卡住超过半天即发报错截图求助。 |
| 范围失控 | 严格执行 §2.1;透视矫正/双列/行内切块列为 Future Work。 |
